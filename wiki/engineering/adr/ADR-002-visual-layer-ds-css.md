# ADR-002: DS CSS as the visual layer

**Status:** accepted by the Architect, 2026-10-12.

## Context

The approved mockups (D046) load exactly three kinds of CSS, in this order: `tokens.css`, `bundle.css`
(every `kh-` class), then composition CSS (`mockup.css` and one file per page) that holds only layout
and uses only DS tokens (`mockup/build.mjs` head template). The founder approved that look. Any second
implementation of the same look (for example rewriting every `kh-` class as Tailwind utilities) can
only drift from it.

The brief asks for Tailwind with a theme generated from the DS tokens, arbitrary values banned, and
says: "If the DS ships its own CSS or Tailwind preset, build on it instead of duplicating it" (§9.12).
The DS ships CSS. `bundle.css` is 70,258 bytes (12,849 gzipped) and contains no hex values
([tokens](../../design-system/tokens.md)). Its globals (`box-sizing`, `body`, `img`, `:focus-visible`)
assume no CSS reset; Tailwind's preflight is a reset and would change headings, lists and images.

Four DS token families collide with Tailwind namespaces (`--radius-*`, `--shadow-*`, `--ease-*`,
`--font-*`), so a naive `@theme` would be self-referential ([tokens](../../design-system/tokens.md),
point 1). The DS has no breakpoint tokens; `bundle.css` hard-codes 720, 768, 900 and 1024 px
([G-03](../../design-system/gaps.md#g-03)).

## Options

1. Port every `kh-` class into Tailwind utilities in JSX. Maximum Tailwind, maximum drift, and a
   second copy of the DS (§4.10 "build once").
2. Drop Tailwind and ship DS CSS plus composition CSS only. Highest fidelity, but contradicts the
   brief's explicit "Use Tailwind CSS for styling".
3. **DS CSS imported directly as the visual layer, composition CSS ported from the mockup, and a
   locked-down Tailwind v4 theme (no preflight, DS-mapped colours, spacing and breakpoints only) for
   layout glue.**

## Choice

Option 3, with these rules (detail in [architecture §4](../architecture.md#4-visual-layer-and-the-token-bridge)):

1. **One CSS entry**, `src/styles/site.css`, imported once by the root layout, in this order:
   `generated/ds-tokens.css` (a derivative of `tokens.css` with its four `@font-face` rules removed,
   generated by script and tested to equal the source otherwise), `generated/fonts.css` (the font faces
   pointing at the derived font files), `design-system/project/components/bundle.css` **imported as is**
   from the read-only folder, `motion/motion.css`, `generated/compose.css` (the composition manifest),
   then Tailwind's `theme.css` and `utilities.css` in cascade layers. **No preflight.**
2. **DS and composition CSS stay unlayered; Tailwind sits in layers.** Unlayered CSS beats layered CSS
   regardless of specificity, so a Tailwind utility can never restyle a DS component: it can only add a
   property nothing else sets. This is a cascade guarantee, not a lint promise.
3. **The Tailwind theme resets every default namespace** (`--*: initial`) and defines only: colour roles
   pointing at DS role variables (`@theme inline`), `--spacing-1` to `--spacing-10` pointing at
   `--space-1` to `--space-10`, `--container-content` at `--content-max`, and four breakpoints equal to
   the widths in `bundle.css` (720, 768, 900, 1024), with a test that parses `bundle.css` and fails if
   they differ. Radius, shadow, easing, fonts and type are **not** in the theme: those belong to the DS
   classes, and leaving them out avoids the four namespace collisions.
4. **Composition classes** use the prefix `ks-` (Kheelona site), BEM like the DS
   (`ks-films__frame`, `ks-beside--center`), each block in a `.css` file colocated with the component
   that owns it, collected into `generated/compose.css` by `scripts/assets/build-compose-css.mjs`
   (prebuild and predev), in a fixed order: ui, sections, chrome, layouts. Every mockup `mk-` class maps
   to one `ks-` class with the same declarations (all 167 blocks are mapped in
   [components §7](../components.md#7-mockup-mk--helpers--where-they-go)), except the Gate A review tool
   classes (`mk-review-*`, `mk-h1*`, `mk-tool`, `mk-later`), which are dropped, and three blocks with CSS
   but no element in any page (`mk-article`, `mk-lead`, `mk-step`), which are not ported.
5. **Values:** tokens only. Literal pixels are allowed in exactly two places: media-query breakpoints
   (the four DS widths and their `max-width` neighbours 719, 767, 899, 1023) and the DS's own literals
   that composition repeats (`outline-offset: 2px`, from `bundle.css`). Three founder exceptions after
   Gate A, each defined once as a named custom property and listed in `test/guards/token-exceptions.ts`:
   `--ks-nudge: 5px` and `--ks-film-focus: 1.05` (D049) and `--ks-wa-green` (D050, DS gap G-20). Type sizes are never restated:
   where the mockup restated a DS type style in pixels to step it up on laptops (the four legal pages,
   the article prose), the build uses **generated responsive type steps** (`ks-type-<style>@<bp>`),
   written by `scripts/assets/build-ds-css.mjs` from the `kh-` type classes in `tokens.css`, so the
   values still come from the DS.
6. **Lint and guards:** no Tailwind arbitrary values (`[...]`), no `(--var)` shorthand, no hex, no `px`
   in class strings, no `style=` attributes except the art-board layer positions (`%`, with rotation),
   the sticker tilt variable, which the DS itself specifies (`10-pages.md:42-52`), and the DS photo ratio
   variable `--kh-ratio` (read by `.kh-photo img` in `bundle.css`). Enforced by
   `test/guards/no-off-token.test.ts` over `src/**/*.{tsx,css}`.

## Consequences

- The built pages render the same classes against the same CSS as the approved mockups, so visual
  parity is a property of the markup, testable by screenshot diff ([ADR-011](ADR-011-guardrails-and-qa-harness.md)).
- CSS weight on first load: about 13 KB (DS components) + 1.5 KB (tokens) + about 12 KB (composition,
  after the four duplicated legal-page files are merged) gzipped, inside the 35 KB budget.
- `bundle.css` also carries classes for app-only components (TabBar, Switch, SocialPost, DeckSlide).
  They cost a few KB. A purged derivative is allowed by brief §4.1 but deferred: it adds a build step
  and a drift risk for little gain.
- Builders write markup with `kh-` classes, not utilities. Tailwind utilities appear only where a
  mockup composition needs a layout property on an element no DS or `ks-` class styles.
