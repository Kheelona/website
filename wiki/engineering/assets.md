# Assets catalogue

Every image, film, font and icon the site uses: its single source, how it reaches the page, and where
it is used. **Check before adding any file.** Rules (brief §4.1, §9.12; [ADR-010](adr/ADR-010-media-pipeline.md)):

- A DS asset is referenced from **one place**: a static import from `@ds/assets/…` inside a media
  primitive. Never copy a DS file by hand; never write into `design-system/`.
- Derivatives are generated by `scripts/assets/*` (or by `next/image` at request time) and say so in a
  header or a row here.
- Non-DS media is allowed only where a decision allows it (films D040, app screens D044, team photos
  B24 when supplied, the Ideabaaz logo B29); the one non-DS colour is WhatsApp green (D050).
- `test/guards/asset-dupes.test.ts` fails on duplicate files and on byte-copies of DS files outside the
  generated folders.

Each task updates only its own rows (Task column). Pages use the same abbreviations as
[components](components.md).

Every generated image carries an EXIF `ImageDescription` naming `build-og.mjs` and its DS source (the
image form of the generated-file header); `test/guards/generated-icons.test.ts` checks sizes, the 200 KB
card budget, opacity, the header, and drift against a fresh in-memory render. Drift is measured per
pixel on decoded, alpha-premultiplied RGBA, for every image and each `favicon.ico` entry: the largest
channel difference at most 16, and at most 0.05% of pixels off by more than 4. That leaves room for
another platform's encoder rounding (the committed files are byte-identical to a fresh render on the
reference machine) but not for a mark: a whole-image mean let a line of text added to a card through.
