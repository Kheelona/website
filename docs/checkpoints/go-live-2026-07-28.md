## Three findings that were real, not theoretical

**1. The pre-order form's Submit button was unreachable.** The iframe was `h-[560px]`; the form
measures **886px**. City and Submit sat below the iframe's own fold, reachable only by scrolling
inside the frame, which many people never realise is possible — on the one panel the whole site
exists to convert. Now 960px, measured against the live embed, with a test that fails below 900.

**2. The canonical host was backwards.** The site went live with `www` primary and the apex 307ing to
it, while every URL the code emits is apex: all 24 sitemap URLs, the canonical tags, robots.txt's
Sitemap line, the WhatsApp share link, every JSON-LD `@id`. Submitting that sitemap would have had
Search Console report 24 "Page with redirect" instead of 24 indexed pages, and the canonical tag
would have pointed Google away from the page it was reading. Fixed in Vercel Domains (apex =
Production, `www` = 308 Permanent) rather than in code, which was the cheaper direction.

**3. GA4 survived that flip by luck of a decision made an hour earlier.** `GA4_HOSTS` lists both
`kheelona.com` and `www.kheelona.com`. A `www`-only allowlist would have gone silently dead the
moment the apex became canonical — and a dead tag reports identically to a site with no traffic.
**Any future host change must update that list.** Law: §8.21-c-i.

## Gotchas worth not rediscovering

**Vercel Web Analytics loads from a per-project obfuscated path** —
`/8f88bf018d5e772b/script.js`, not `/_vercel/insights/`, because Vercel randomizes it to survive ad
blockers. I concluded it was missing on the live site for exactly this reason before checking
`window.vai`. Verify by that global or the hash path, never the literal insights path.

**The preview still shows the "opens soon" card.** The Tally env var is production-scoped. Expected.

**`NEXT_PUBLIC_*` values are inlined at build time.** Setting one in Vercel does nothing to an
existing deployment; it needs a redeploy. This cost one round trip.

## Decisions recorded, not to be re-litigated

**Testimonials stay as they are.** The live site attributes three drafted quotes to named people
(Shweta, Priyamvada, Gaurav, "Pilot parent") with nothing marking them illustrative. Raised once with
the founder on the day the site went public, including that fabricated endorsements are what India's
Consumer Protection Act and the ASCI code treat as misleading advertising. **Founder's decision: leave
them.** Do not re-raise, do not remove. Real quotes swap in cleanly.

**No cookie-consent banner.** GA4 sets cookies. Consent Mode without UI either denies everything
(measuring nothing) or grants everything (changing nothing), and a banner is new UI the founder has
not asked for. So: disclosure on /privacy plus a documented opt-out, banner left open.

**GA4 measurement ID is hardcoded**, not an env var. It is a public client-side identifier, and the
env var it replaced was never read by any code, so keeping it meant a founder gate for no security
gain. The host allowlist is what makes it safe.
